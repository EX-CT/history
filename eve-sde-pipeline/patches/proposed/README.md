> **Revision 4:** 0101, 0102 and 0103 were reviewed by engine owner A and moved to `patches/`, where they are
> applied by default. See CHANGELOG.md. No patch is pending review right now.

Generated by `tools/make_proposed_patches.py` from the `gap` rows of
[`reports/pyfa-effects-coverage.md`](../../reports/pyfa-effects-coverage.md). These are effects for which CCP
ships no `modifierInfo` and that no EXCT engine special-cases yet. Each patch describes the behaviour as Pyfa
implements it (attribute X modified by attribute Y, with operation and filter). It does not copy Pyfa code.

The patches are **not** in release datasets. Applying them changes fit results compared with current bench parity, so an
engine owner has to review each one first. To test locally: `python -m sdepipe build --sde … --out … --with-proposed`.
When a patch is promoted, move it to `patches/`, bump `DATASET_REVISION`, and record the change in `CHANGELOG.md`.

## Gaps that are not expressible as modifiers (engine work)

- `powerBooster` (capacitor boosters): Pyfa sets reload time to 10 s and forces reload in its calculations.
  It then turns the charge's `capacitorBonus` into a negative `capacitorNeed`. This is a cap-stability stat rule.
- `doomsdayAOEECM`: adds projected ECM jam strength (sensor-type-specific `scan<Type>StrengthBonus`, times resistance).
- `doomsdayAOENeut`: adds a projected cap drain (`energyNeutralizerAmount` every `duration`).
- Environment weather/cloud beacons (`weather_*`, `aoe_beacon_*`): no modifiers needed. The dataset lists the
  buffs they emit in `environment.effect_beacons[*].dbuffs`. Engines should apply these like fleet command bursts.
